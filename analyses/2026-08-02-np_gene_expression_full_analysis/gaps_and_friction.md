# Gaps and friction

Transitional log of methodology / KG / tooling friction encountered during this analysis. Distinct from decisions (which live in each step's `notebook.md`). Append-only.

## 2026-08-02 — "nitrogen" treatment_type mixes starvation with alternate-N-source growth

While enumerating nitrogen experiments in step 2, `list_experiments(treatment_type=['nitrogen'], ...)` returned both true starvation/deprivation contrasts and "growth on alternate N source (cyanate/urea/nitrite) vs N-replete" contrasts under the same `treatment_type` tag. These are different biological questions (nutrient depletion vs. alternate-source utilization), but nothing in the KG schema (`treatment_type`, `background_factors`) distinguishes them — only the free-text `treatment`/`control` fields do. This mattered here because several of the analysis's nitrogen-annotated genes (`cynA/B/D/S`, `ureA–G`, `nirA`) are themselves alternate-N-source-utilization genes, so the excluded experiments were arguably the most on-target evidence for those specific genes. Worked around by manually reading `treatment`/`control` text per experiment and excluding by experiment ID (see `2_kg_selection/scripts/02_list_np_experiments.py`). Downstream impact: the analysis's nitrogen-side results for `cyn*`/`ure*`/`nirA` are conservative relative to what the KG actually contains — a caveat to carry to step 6. Phosphorus treatment_type had no equivalent split. Methodology takeaway: when a gene's annotated function is "use compound X as a nutrient source," treatment_type alone is not enough to tell whether an experiment is on-target — the treatment/control text must be read.

## 2026-08-02 — Strain scope (SS120) surfaced late, required a step-2 redo

The researcher's study excludes SS120 (CCMP1375), but this was not mentioned during step 1 or step 2's co-define — it only surfaced during step 3's co-define, after step 2 (experiment enumeration, gene-locus resolution) had already been committed with SS120 included. Handled via the redo path: step 2's script/data/notebook were regenerated without SS120 and recommitted as a new commit (prior commit `2da4c3b` preserved in history). Process takeaway: for analyses that build on a researcher's specific named strain/study set (as this one explicitly does, inheriting from the "15 strains 4 media" paper), confirm the exact strain list during step-1 co-define rather than assuming "all strains with data in the KG" is in scope.

## 2026-08-02 — METABOLOMICS-type experiments silently carry no gene-level DE data

`list_experiments(treatment_type=['phosphorus'], ...)` happily returns METABOLOMICS-omics-type experiments alongside RNASEQ/PROTEOMICS/MICROARRAY ones, and step 2's first pass counted MIT9301's 2 metabolomics experiments as valid phosphorus evidence without flagging anything unusual — `omics_type` was visible in the experiment table but its practical consequence (zero gene-level DE) wasn't obvious until `differential_expression_by_gene` was actually called against those experiment IDs and returned empty results. This wasn't caught in step 2's QC because step 2 only enumerated experiments, it didn't yet query DE data per experiment. Downstream impact: MIT9301 dropped out of the analysis entirely (2nd redo of step 2), and `ptxB/phnD2` lost its only evidence. Methodology takeaway: when an analysis's question is specifically about gene expression, step 2's experiment enumeration should filter to (or at minimum flag) omics types that carry gene-level DE edges (RNASEQ/PROTEOMICS/MICROARRAY) rather than deferring that check to whenever a DE query happens to be run against those experiments.

## 2026-08-02 — Starvation-induction method not captured in the KG

The researcher asked whether each experiment's starvation was induced by centrifugation/resuspension or by dilution/transfer into low-nutrient medium. None of the KG's experiment fields (`medium`, `treatment`, `control`, `experimental_context`, `growth_phases`) record this protocol detail — only the resulting medium formulation is described (e.g. "Pro99 lacking supplemented nitrogen"), which is a weak indirect signal at best, not a confirmed induction method. Flagged as a gap rather than filled from outside knowledge; researcher decided this detail isn't needed for the analysis and to proceed without it. If a future analysis needs induction-method detail, it will need to come from reading the source publications directly — it is not in this KG build's schema.

## 2026-08-02 — hit_rate() bug: experiment_ids spanning multiple organisms

The step-4 worked example only tested MED4 (a single organism), so it didn't catch that `differential_expression_by_gene` rejects an `experiment_ids` list spanning multiple organisms. `hit_rate()`'s groups in step 5 pass "all nitrogen experiments" or "all phosphorus experiments" as one flat list, which does span organisms (e.g. nitrogen includes both MED4 and MIT9313 experiment IDs) — this raised a `ValueError` on the first real run. Fixed by narrowing `experiment_ids` to each organism's own subset via `list_experiments(experiment_ids=..., organism=...)` before calling the DE function, inside `hit_rate()`'s per-organism loop. Re-ran the step-4 worked example after the fix — results unchanged (MED4-only case wasn't affected by the bug). Methodology takeaway: a worked-example verification against a single strain doesn't exercise multi-organism code paths — worth verifying against at least 2 organisms when the method is meant to batch across strains.
